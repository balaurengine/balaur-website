Rune is the scripting language. A script is one object per node, and every
component on the node is a field it calls.

{/* truncate */}

<Clip name="scripting_live" alt="A script changed and saved while the scene runs, the new code live with the state kept" />

- `update(this, dt)` runs every frame, and `fixed_update` on the fixed step,
  before physics.
- `exports()` returns the defaults. A scene overrides only what it changes,
  and the inspector lists them per node.
- Each component is a field on the node with every function that drives it,
  plus `get()`, `set()`, `has()` and `remove()`.
- The [modules](/docs/reference/modules), [components](/docs/reference/components)
  and [assets](/docs/reference/assets) references are read out of a running
  engine, and CI fails when they drift.

```rune
pub fn exports() {
    #{ speed: 2.0 }
}

pub fn fixed_update(this, dt) {
    this.node.body2d.apply_impulse(this.speed * dt, 0.0);
}
```

## Tooling

![The completion popup under the caret, on a module path](/img/manual/script_completion.webp)

- After `physics2d::` completion lists that module, and after `node.body2d.`
  what acts on that component.
- `⌘B` goes to a definition, `⌘⇧R` renames across files, and `⌥⇧F` formats.
- The Problems dock checks on save for a missing script, prefab or asset, and
  for a shader that will not link.
- A VS Code extension spawns `balaur lsp`, which runs the same checks.

![The Script persona with platform.rn open on the bad call, and the Problems dock under it naming the line and the method](/img/blog/script_problems.webp)

- `balaur check` resolves every component method a script calls against the
  scene it runs on, and a misspelled one names its file and line.
- Findings are warnings, and `--strict` makes them errors for CI.
