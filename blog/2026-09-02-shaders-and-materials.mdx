Shaders are written in WESL and linked to WGSL at run time. A material asset
names one and its params are read off the shader, saving a shader relinks it
in place, and there are debug channels to see what a pass is doing.

{/* truncate */}

<Clip name="shader_preview" alt="A material in the inspector, its shader open in the code editor, the UV channel drawn instead of the picture, and a save that relinks the sprite in place" />

- WESL is WGSL plus imports, `@if` variants and dead-code elimination,
  linked to WGSL at run time. A 2D shader imports `package::sprite`; a 3D
  one imports `package::mesh` and calls `shade(in)` for the scene's lights.
- A `material` asset names a shader and its `[params]`, which are read off
  the linked shader. `sprite`, `shape2d`, `shape3d` and `mesh` take one, and
  a node without one draws with the built-in material.
- Saving a shader relinks every material naming it and rebuilds every node
  drawing with it. A shader that will not link is reported with its source
  line, and the node keeps the built-in material.
- `render::set_channel("uv")` draws the scene's UVs. `normals`, `depth` and
  `albedo` are the other channels.

```toml
# materials/glow.toml
type = "material"
shader = "shaders/glow.wesl"

[params]
speed = 2.0
rings = 5.0
tint = "#ffb347"
```

A shader is outside the digest. `time()` is render time, not the tick. A
function marked `@const` runs on the CPU in headless tests.

`examples/shaders` is a glow material on a sprite beside a plain one. It
[runs in the browser](/examples/?play=shaders).
