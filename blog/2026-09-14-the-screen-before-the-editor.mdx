Started with no project, the editor opens on a screen rather than a usage
line. It has three tabs: your projects, the examples that ship with it, and
the engine build itself.

{/* truncate */}

![The Projects tab: a filter, the three ways to start, and the projects this machine has opened with their paths, times and engine versions](/img/manual/project_manager.webp)

- The screen is drawn by the editor's own widgets, hot reloads when its
  script is edited, and folds to one column on a phone. Godot opens a separate
  window for it; here it is the same window.
- Each row keeps when the project was last opened and which engine opened it.
  A folder that has gone stays in the list and says so, since it is usually an
  unplugged disk.
- Opening a project closes the one you came from. One process is one project:
  the export and import modules and the file root are built for the project
  the editor booted with.

## Examples, not an empty state

![The Examples tab: a card per example project, each with its name and a line saying what it is](/img/manual/project_examples.webp)

The twelve example projects ship beside the editor, each with a picture of
itself running. Opening one copies it into your projects folder and opens the
copy, so the shipped example stays as it was.

## Which engine this is

![The Engine tab: this build and whether it is current, the channel to follow, and the releases on it](/img/manual/engine_versions.webp)

- Follow picks one line: `alpha`, `beta`, `rc`, `stable` or `nightly`. The
  releases under it are that line's, newest first, with the installed one
  marked.
- The release feed is read once, when the tab opens, rather than once per
  channel.
- The tab calls the same functions as `balaur update`, which follows the same
  channels and tags.
