Import settings as a TOML sidecar beside the asset. Project-wide defaults per
kind in `project.toml`. Nearest filtering, so pixel art draws with hard edges.

{/* truncate */}

## What landed

- **Sidecar.** The double extension sorts beside its image in a listing and
  cannot collide with a scene or a clip named `hero`.
- **Project default.** `[import.texture]` in `project.toml`; a sidecar
  overrides one key at a time.
- **Every kind.** A file's kind comes from its extension: texture, audio,
  font or model. One resolver reads them all.
- **Two keys reach the renderer.** `filter`: `"nearest"` or `"linear"`.
  `srgb = false` for an image that is data, not colour: a normal map, a mask.
- **One re-upload.** The resolved settings are part of the name a texture is
  uploaded under, with the file's modification time, so editing a sidecar
  re-decodes one image.
- **Pixels, never sizes.** A sprite's extent comes from the image header, so
  a headless run computes the same world as a windowed one and import
  settings stay out of the digest. Downscaling for a phone is an export key.

```toml
# art/hero.png.toml
filter = "nearest"   # pixel art, drawn crisp instead of blurred
srgb = true          # false for a normal map or a mask, which carry data
```

```toml
# project.toml
[import.texture]
filter = "nearest"
```

The editor writes the sidecar for you. Pick a picture in the Assets dock and
the Import tab, beside the Inspector, shows one row per key, each saying whether
the value is the file's own, the project's or the engine's default. Clearing a
row drops the key, and an empty sidecar is deleted.

![The Import tab showing filter and srgb for a selected picture](/img/manual/import_dock.webp)

Written but not wired: `repeat`, `mipmaps`, `anisotropy` and premultiplied
alpha, which wait on the renderer exposing a whole sampler. On the
[roadmap](/docs/roadmap); [Import settings](/docs/manual/scenes#import-settings)
is the manual.
