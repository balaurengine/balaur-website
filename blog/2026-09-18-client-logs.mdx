Every run now writes its log to a file, and a game can ship its log to Gamend. A crash leaves its last lines on disk, and the next launch sends them.

{/* truncate */}

![The Logs tab while the game plays](/img/manual/gamend_logs.webp)

## The log file

- Each run writes `logs/run.log` in the game's user data folder and keeps the last five as `run.1.log` and on.
- `[log] file = false` turns it off, and `[log] keep` sets how many runs stay.
- Lines logged before the file opens, `init` included, go in first.
- A panic is written to the file before the process dies.
- Scripts read the log with `log::since(cursor)`, which answers each line once and counts the lines the buffer dropped.

## Shipping to Gamend

- `addons/gamend/log_sink.rn`, on a node that lives as long as the game, ships its lines.
- It asks the server's policy what to collect, and sends nothing until it answers.
- A batch goes at 50 lines, every 10 seconds, and at once on an error.
- A line repeated back to back goes once, with its count.
- Unsent lines wait in a save slot. The next launch sends them, with the tail of the last log file when that run logged an error.
- A game played in the editor sends its own lines only.

## One id per run

- `gamend::run_id()` names the run.
- Every API call sends it as `x-gamend-session`, the socket as `client_session`, and each log batch as its session.
- The server files a run's client lines and the server lines it caused under that id.
