# Your first project

This tutorial creates a project, builds a small 3D scene with physics, and
demonstrates hot reload. It follows the `examples/hello` project from the
repository.

## Create and run

```bash
cargo run -p balaur_cli -- new my-game
cargo run -p balaur_cli --features window -- run my-game
```

`new` scaffolds a `project.toml`, a main scene with one node, and a script:

```rust
// scripts/hello.rn
pub fn init(this) {
    println!("hello from {}", this.node.name());
    this.elapsed = 0.0;
}

pub fn update(this, dt) {
    this.elapsed += dt;
}
```

A script is a set of free functions taking the instance first. The engine
makes one instance per node the script is attached to, calls `init` once
and `update(dt)` every frame, and puts the owning node on `this.node`.

## Build a scene

Replace `scenes/main.toml` with a ground plane, a ball, and a spinner. Scene
keys such as `body3d`, `collider3d`, and `shape3d` are components contributed by the
physics and rendering plugins:

```toml
[[nodes]]
name = "Ground"
position = [0, -1, 0]
color = [0.3, 0.55, 0.3]
body3d = "static"
collider3d = { kind = "cuboid", half_extents = [10, 0.5, 10] }
shape3d = { kind = "cuboid", half_extents = [10, 0.5, 10] }

[[nodes]]
name = "Ball"
position = [0, 6, 0]
script = "scripts/ball.rn"
shape3d = { kind = "ball", radius = 0.5 }

[[nodes]]
name = "Spinner"
position = [2.5, 0.5, 0]
color = [0.2, 0.4, 0.9]
script = "scripts/spinner.rn"
shape3d = { kind = "cuboid", half_extents = [0.5, 0.5, 0.5] }
```

## Add physics from a script

Components can come from the scene file or from code. The ball sets up its own
physics in `init`:

```rust
// scripts/ball.rn
pub fn init(this) {
    physics3d::add_body(this.node, physics3d::BODY_DYNAMIC);
    physics3d::add_ball_collider(this.node, 0.5);
    this.reported = false;
}

pub fn update(this, dt) {
    let y = this.node.position().y;
    if y < 0.2 && !this.reported {
        this.reported = true;
        println!("ball touched down at t = {:.2}", engine::time());
    }
}
```

Because the simulation is deterministic, the touchdown time is the same on
every run, headless or windowed, on every platform.

## Read input

The spinner rotates continuously and reverses direction on Space:

```rust
// scripts/spinner.rn
const SPEED = 2.0;

pub fn init(this) {
    this.angle = 0.0;
    this.direction = 1.0;
}

pub fn update(this, dt) {
    if input::just_pressed(input::KEY_SPACE) {
        this.direction = -this.direction;
    }
    this.angle += dt * SPEED * this.direction;
    this.node.set_rotation_euler(0.0, this.angle, 0.0);
}
```

Values a binding accepts are named constants rather than spelled strings:
`input::KEY_SPACE`, `physics3d::BODY_DYNAMIC`, `ui::ANCHOR_TOP_LEFT`. The
full list is in the [script API reference](../reference/script-api.md).
Note the `0.0`: integers and floats never mix in Rune, and the angle is a
float.

## Hot reload

While `run` is going, change `SPEED` in `spinner.rn` and save. The new code
is live within milliseconds and the current angle survives: the engine
recompiles the file into a new unit and swaps it for the old one; every
instance keeps its state object, and the next call resolves against the new
code.

If the save does not compile, the old code keeps running and the error is
reported once.
