# Quality

Every rule here is a script that fails, and every script runs on every push
and pull request.
[docs/QUALITY.md](https://github.com/balaurengine/balaur/blob/main/docs/QUALITY.md)
is this list with the file paths.

## Workflows

One workflow owns the triggers and calls four, so a red X names itself.

| Workflow | Covers |
| --- | --- |
| `lint` | everything that reads the code without running it |
| `docs` | both kinds of documentation |
| `test` | everything that runs the engine |
| `build` | everything that produces a download |

A pull request runs all four. Only the job that publishes a release is skipped.

## The compiler

- A pinned toolchain, so every machine runs one linter version.
- Formatting checked, and Clippy with warnings denied, on Linux, macOS and
  Windows. Platform code compiles nowhere else.
- Once more per off-by-default feature, because code behind one is not
  compiled at all: the windowed backend (wgpu, egui, the macOS dock icon),
  extensions (dlopen and the cdylib), the Apple stores.
- One example extension outside the workspace, the only proof that an
  extension builds without the engine's build tree.

## House lints

Three scripts, at two severities. **Error** fails CI and is mechanical.
**Report** prints only, because failing a build on a heuristic teaches people
to game the heuristic.

| Rule | Fails on |
| --- | --- |
| platform float math | `.sin()`, `.powf()` and the rest that differ between operating systems; `sqrt`, `abs` and `floor` are exact everywhere and allowed |
| nondeterministic iteration | iterating a hash map or set, which leaks hash order into behaviour |
| channels outside the recorded seam | anything that could reach the outside world during a replay |
| unjustified `unwrap` | `unwrap` or `expect` outside tests with no justification |
| `allow` without a reason | an `#[allow(..)]` that does not say why |
| TODO without an issue | a TODO with nothing behind it |
| function and file length | 120 lines, 1200 lines |
| naming | the mechanical half of the naming rules, a dozen checks |
| two Rune traps | shapes that compile and then misbehave |

| Also held | How |
| --- | --- |
| The ratchet | A baseline records the violations predating each rule, per file. Above that count fails, deleting a line is progress, adding one by hand is not allowed |
| Comments | One or two lines stating a constraint, in Rust, Rune, Python, shell, YAML and TOML. A block over three lines fails, and so does one that restates the line under it |
| Names | Decided once and checked mechanically, because a rename breaks someone's project. The API half boots the engine and reads what it offers, so a name a script cannot reach is not API |

## Determinism

Two ways [determinism](./manual/determinism.mdx) breaks, both compile errors:

- Wall-clock time. `Instant::now` and `SystemTime::now` are banned outright.
- Entropy. Unseeded randomness is banned; a call outside the simulation
  carries a written reason.

Line endings are pinned in the index, or a Windows checkout would export
different bytes from the same sources. CI then checks four things:

1. Two exports agree. Every example is exported twice in separate processes,
   and the files must be byte-identical.
2. Every platform exports the same bytes. Linux, macOS and Windows upload pack
   digests, and the digests are diffed.
3. Every platform steps the same simulation. One digest per tick, 600 frames,
   five projects. The first differing line is the tick they parted on.
4. The same sources build the same binary. Built twice on one runner and
   compared, so a divergence can be bisected.

A change that alters a recorded digest has to say why.

## Tests

Around 1,200 tests across 22 crates, on three desktop platforms. Beyond the
plain run:

- the extension path, off by default and never otherwise built;
- a build with the optional subsystems switched off;
- suites where a full app boots and talks over real sockets.

A test's name is a sentence about behaviour:
`freeing_a_node_frees_its_children`, not `test_free`. A test asserting from
inside a script carries one control proving the script ran.

## Every example, twenty ways

Six example projects, twenty passes each, on three platforms:

| Pass | What it proves |
| --- | --- |
| run | dev mode, straight from the sources |
| export, twice | the two packs match |
| play | the exported pack runs with no sources and no compiler |
| edit, sixteen times | the editor is a Balaur project, booted headless against every example |

The editor passes drive undo, layout, rigging, the polygon tool, plugins, the
clipboard, the assets dock, picking, script properties, prefab instances,
placement, the profiler, session recording and the theme switch.

Two bars for every pass: a clean exit and a clean log. A logged error fails
the run, and so does an editor scene node the editor cannot resolve.

Headless covers loading, mirroring and asset rebinding, not drawing. Drawing
is one screenshot per editor screen, rendered offscreen against a committed
catalogue, diffed before any change to the editor's shell.

## Documentation that cannot drift

- Rustdoc builds with warnings denied, which catches dead intra-doc links.
- The generated docs (script API, components, assets, behaviour) are rebuilt
  from a booted engine on every push, and the build fails on any diff.
- The third-party notices file is regenerated and diffed the same way.
- This site builds its [reference](./reference/index.md) from that data, so
  the published docs cannot describe an engine that does not exist.

## Performance

- Feature tests and performance tests stay apart.
- Budgets assert orders of magnitude, never percentages. A CI runner is shared
  and throttled, so a percentage gate fires on noise.
- Every ceiling is ten times a measured run, written in one place.
- They catch an accidental O(n²), a lock held across a frame, or a compile
  moved into the hot path. A five percent regression is what the
  [benchmarks](./benchmarks.md) are for.

## Supply chain

- Advisories, bans and sources are checked on every push with all features on,
  so the audit reaches the windowed tree a headless build never compiles.
- Yanked crates are denied, and so are unknown registries and git sources.
- The two forks the engine uses are allowlisted by name, with the reason
  recorded.

## Releases

- `SHA256SUMS` and build-provenance attestations, verifiable with
  `gh attestation verify`.
- Every push exports a game through the same published actions a player's own
  repository calls, against the engine that run just built.

## What review is left to do

Everything above is mechanical. Review spends its
attention on what a script cannot check:

- whether the change serves the [principles](./principles.mdx);
- whether the name is the right name;
- whether the test asserts on behaviour a caller can see.

One concern per pull request, with code, tests and docs landing together,
and the roadmap moving when the change moves something on it.
