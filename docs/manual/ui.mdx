# UI

Two UI layers, both script-facing. Which one you want depends on whether the
interface belongs to the game or to a tool:

- **`widget`**, a component on a scene node. Retained: saved with the scene,
  edited in the inspector, previewed in the editor viewport. This is game HUD —
  a score readout, a menu button.
- **the `ui` module**, immediate-mode egui redrawn every frame from a script's
  `draw_ui`. This is what tools and the editor itself are built from.

## Widgets: game HUDs as scene nodes

There is one `widget` component, not one per kind of element. What it draws is
its `kind` — `label`, `button` or `panel` — the engine's convention throughout:
a component that comes in variants selects them with `kind`. A button is a
widget anchored to a screen corner or the centre:

```toml
[[nodes]]
name = "Score"

[nodes.widget]
kind = "label"
text = "Score 0"
anchor = "top_left"
x = 20
y = 16
font_size = 22
text_color = "#2b2b2b"
```

A button acts in one of two ways: `on_click` names a method on that node's own
script, or the read-only `clicked` property is true for the frame the press
happened and a script polls it:

```toml
[nodes.widget]
kind = "button"
text = "Start"
on_click = "start_pressed"
```

```rune
pub fn start_pressed(this) {
    log::info("start");
}

// or, without on_click:
pub fn update(this, dt) {
    if this.node.widget.get().clicked {
        log::info("start");
    }
}
```

Widgets live in the scene tree like any node, so they are saved with the
scene, editable in the editor, and updatable from scripts through the component
handle.

![The Interface persona: examples/angrynerds' Score, Birds, Hint and Restart widgets in the tree, the HUD over the safe area, and the Restart button in the inspector](/img/manual/ui_widgets.webp)

`on_click` names a method on the button's own node, so a button that acts on
another node's script forwards the call:

```rust
// scripts/restart_button.rn, on the Restart node
pub fn on_restart(this) {
    this.node.get_node("../Game").call("restart");
}
```

A handle's `set` builds the component from your table over the schema's
defaults rather than merging into what is there, so read the table first to
change one property:

```rune
let w = this.node.widget.get();
w.text = "Score 10";
this.node.widget.set(w);
```

Panels size to their content when `width` or `height` is 0, and `visible`
hides a widget without losing its state. `ui::set_widget_layer` scopes and
toggles the layer.

## The `ui` module: immediate-mode UI

For tools and anything beyond a HUD, the `ui` module exposes immediate-mode
[egui](https://github.com/emilk/egui) to scripts, through a `draw_ui`
lifecycle method that runs once per frame inside the egui pass:

```rune
pub fn draw_ui(this) {
    let k = this.theme;
    ui::left_panel("outline", #{ width: 260, fill: k.bg }, || {
        ui::label("Nodes", #{ size: 14, color: k.text });
        if ui::pill("Add node", #{ fill: k.accent }) {
            // ...
        }
    });
}
```

Panel and container calls take a closure and push their child UI around it, so
a script composes layouts exactly like Rust egui code. Widgets that change
return a tuple — `let (text, changed) = ui::text_field(...)`. The set includes
panels, labels, pills, toggles, sliders, drag values, dropdowns, text fields,
modals, scroll areas, menus, shortcuts, and `ui::code_editor`, an editable
Rune-highlighted buffer.

Widgets take colors per call, so complete themes live in scripts and hot reload
with them. Fonts load from `<project>/fonts/*.ttf`, with the families
`heading` / `ui` / `mono` always available.

All dimensions are design pixels: `ui::set_scale(f)` multiplies every metric
and the query functions divide back, so scripts author against the design's
pixel values at any zoom. HiDPI is separate and automatic.

The editor's entire interface is built with this module; see
[The editor](./editor.mdx).
