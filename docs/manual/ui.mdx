# UI

Two layers, both script-facing.

| Layer | What it is | For |
| --- | --- | --- |
| `widget` | A component on a scene node. Retained: saved with the scene, edited in the inspector, previewed in the viewport | A game HUD, a settings screen, a whole tool |
| the `ui` module | Immediate-mode egui, redrawn every frame from a script's `draw_ui` | A canvas that paints itself: a timeline, a weight table |

The editor's shell, docks, inspector and tab rows are `widget` nodes in
`editor/scenes/main.toml`. Its four painting views use the `ui` module.

## Widgets: game HUDs as scene nodes

```toml
[[nodes]]
name = "Score"

[nodes.widget]
kind = "label"
text = "Score 0"
anchor = "top_left"
x = 20
y = 16
font_size = 22
text_color = "#2b2b2b"
```

- One `widget` component. `kind` says what it draws: `label`, `button` or
  `panel`. Every component with variants selects one with `kind`.
- Widgets are scene nodes: saved with the scene, edited in the editor,
  updated through the component handle.

![The Interface persona: examples/angrynerds' Score, Birds, Hint and Restart widgets in the tree, the HUD over the safe area, and the Restart button in the inspector](/img/manual/ui_widgets.webp)

A button acts in one of two ways:

```toml
[nodes.widget]
kind = "button"
text = "Start"
on_click = "start_pressed"
```

```rune
pub fn start_pressed(this) {
    log::info("start");
}

// or, without on_click:
pub fn update(this, dt) {
    if this.node.widget.get().clicked {
        log::info("start");
    }
}
```

```rust
// scripts/restart_button.rn, on the Restart node
pub fn on_restart(this) {
    this.node.get_node("../Game").call("restart");
}
```

- `on_click` names a method on the node's own script. A button acting on
  another node forwards the call.
- `clicked` is read-only and true for the frame of the press.

```rune
let w = this.node.widget.get();
w.text = "Score 10";
this.node.widget.set(w);
```

- A handle's `set` builds the component from the given table over the
  schema's defaults. To change one property, `get` first.
- Panels size to their content when `width` or `height` is 0.
- `visible` hides a widget and keeps its state. `ui::set_widget_layer` scopes
  and toggles the layer.

## The kinds

| Group | Kinds |
| --- | --- |
| Text | `label`, `field`, `text_area`, `code` |
| Controls | `button`, `check`, `dropdown`, `slider`, `drag_value`, `color`, `progress`, `menu` |
| Data | `list`, `tree`, `table` |
| Boxes | `panel`, `row`, `column`, `grid`, `flow`, `scroll`, `tab`, `fold`, `dialog` |
| Other | `image`, `separator`, `draw` |

- **`list`** — rows from `options`; `text` is the one picked. A row splits on
  U+001F into an icon, a label, a trailing note and an `#rrggbb`. With
  `columns` above one, rows flow into a grid of cards (`ItemList` in icon
  mode) and `row_height` is the card's height.
- **`tree`** — a `list` whose rows nest. One leading tab is one level. The
  fold caret is the kind's own.
- **`table`** — one row per line, one cell per column. `placeholder` holds
  the column names, split the same way.
- **`code`** — an editor with gutter, syntax colours and caret. The same
  editor as the `ui` module's `code_editor`.
- **`draw`** — a rect a script fills. The node owns the placement, the script
  owns the contents.

Only the rows on screen are built. A long list costs its viewport.

## Layout

A container hands its children rects.

- **`grow`** — the share of leftover space this box takes along the
  container's direction. Zero takes only its own size.
- **`gap`** — space between children. **`padding`** is space inside the
  container's edge.
- **`align`** — where children sit across the container's direction.
- **`justify`** — how they spread along it: `start`, `center`, `end`,
  `between`, `around` or `evenly`.
- **`width`** — the box, with `height`, `min_width` and `min_height`. Zero
  hugs the content.
- **`handle`** — the grab width of the seams between children. A drag writes
  the new size onto the neighbour that states one.

Layout is [taffy](https://github.com/DioxusLabs/taffy), the layout engine
Dioxus and Blitz use. It runs over the whole tree before drawing. `ui::widget_rect`
reads a rect back in the same frame.

## Themes and roles

A `widget_theme` asset says how each kind looks. A widget takes the theme of
the nearest ancestor that names one.

```toml
type = "widget_theme"

[colors]
ink = "#0e1116"
accent = "#6fa4d8"

[button]
fill = "ink"
radius = 6
padding_x = 10

[button.hover]
fill = "accent"

[roles.primary]
fill = "accent"
color = "#f6f8fb"
strong = true
```

- `[colors]` names colours the rest of the file refers to.
- `[<kind>]` is that kind's look. A kind the file leaves out keeps the
  built-in one.
- `[roles.<name>]` is the same table under a name. A widget takes it with
  `role = "primary"`, over its kind's.
- `[<kind>.hover]` and `[<kind>.active]` say how it looks under the pointer.
- A widget's own `fill`, `stroke`, `radius`, `text_color`, `font_size` and
  `font` win over the theme.

Also on every widget: `tooltip`, `icon` (a glyph from the theme's icon
family, drawn before the caption) and `disabled`.

## The `ui` module: immediate mode

```rune
pub fn draw_ui(this) {
    let k = this.theme;
    ui::left_panel("outline", #{ width: 260, fill: k.bg }, || {
        ui::label("Nodes", #{ size: 14, color: k.text });
        if ui::pill("Add node", #{ fill: k.accent }) {
            // ...
        }
    });
}
```

- `draw_ui` runs once per frame inside the
  [egui](https://github.com/emilk/egui) pass.
- Panel and container calls take a closure for their children, as Rust egui
  code does.
- A widget that changes returns a tuple:
  `let (text, changed) = ui::text_field(...)`.
- The set: panels, labels, pills, toggles, sliders, drag values, dropdowns,
  text fields, modals, scroll areas, menus, shortcuts, and `ui::code_editor`,
  an editable Rune-highlighted buffer.
- For canvases: a timeline's lanes, a weight table, a painting tool. A `draw`
  node places one in a tree of widgets.
- Colours are per call. A theme lives in a script and hot reloads with it.
- Fonts load from `<project>/fonts/*.ttf`, with `heading`, `ui` and `mono`
  always available.
- All dimensions are design pixels. `ui::set_scale(f)` multiplies every metric
  and the query functions divide back. HiDPI is separate and automatic.

The editor's four painting views use this module inside `draw` nodes. See
[The editor](./editor.mdx).
