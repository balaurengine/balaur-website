# UI

Two layers, both script-facing. Which one depends on whether the interface
belongs to the game or to a tool.

| Layer | What it is | For |
| --- | --- | --- |
| `widget` | A component on a scene node. Retained: saved with the scene, edited in the inspector, previewed in the viewport | A game HUD: a score readout, a menu button |
| the `ui` module | Immediate-mode egui, redrawn every frame from a script's `draw_ui` | Tools, and the editor itself |

## Widgets: game HUDs as scene nodes

```toml
[[nodes]]
name = "Score"

[nodes.widget]
kind = "label"
text = "Score 0"
anchor = "top_left"
x = 20
y = 16
font_size = 22
text_color = "#2b2b2b"
```

- One `widget` component, not one per kind of element. What it draws is its
  `kind`: `label`, `button` or `panel`. A component that comes in variants
  selects them with `kind`, throughout the engine.
- Widgets live in the scene tree like any node, so they are saved with the
  scene, editable in the editor, and updatable through the component handle.

![The Interface persona: examples/angrynerds' Score, Birds, Hint and Restart widgets in the tree, the HUD over the safe area, and the Restart button in the inspector](/img/manual/ui_widgets.webp)

A button acts in one of two ways:

```toml
[nodes.widget]
kind = "button"
text = "Start"
on_click = "start_pressed"
```

```rune
pub fn start_pressed(this) {
    log::info("start");
}

// or, without on_click:
pub fn update(this, dt) {
    if this.node.widget.get().clicked {
        log::info("start");
    }
}
```

```rust
// scripts/restart_button.rn, on the Restart node
pub fn on_restart(this) {
    this.node.get_node("../Game").call("restart");
}
```

- `on_click` names a method on that node's own script, so a button acting on
  another node forwards the call.
- `clicked` is read-only and true for the frame the press happened, for a
  script that would rather poll.

```rune
let w = this.node.widget.get();
w.text = "Score 10";
this.node.widget.set(w);
```

- A handle's `set` builds the component from your table over the schema's
  defaults rather than merging into what is there, so read the table first to
  change one property.
- Panels size to their content when `width` or `height` is 0.
- `visible` hides a widget without losing its state, and
  `ui::set_widget_layer` scopes and toggles the layer.

## The `ui` module: immediate mode

```rune
pub fn draw_ui(this) {
    let k = this.theme;
    ui::left_panel("outline", #{ width: 260, fill: k.bg }, || {
        ui::label("Nodes", #{ size: 14, color: k.text });
        if ui::pill("Add node", #{ fill: k.accent }) {
            // ...
        }
    });
}
```

- `draw_ui` runs once per frame inside the egui pass, exposing
  [egui](https://github.com/emilk/egui) to scripts.
- Panel and container calls take a closure and push their child UI around it,
  so a script composes layouts as Rust egui code does.
- A widget that changes returns a tuple:
  `let (text, changed) = ui::text_field(...)`.
- The set: panels, labels, pills, toggles, sliders, drag values, dropdowns,
  text fields, modals, scroll areas, menus, shortcuts, and `ui::code_editor`,
  an editable Rune-highlighted buffer.
- Colours are per call, so a complete theme lives in a script and hot reloads
  with it.
- Fonts load from `<project>/fonts/*.ttf`, with `heading`, `ui` and `mono`
  always available.
- All dimensions are design pixels. `ui::set_scale(f)` multiplies every metric
  and the query functions divide back, so a script authors against the
  design's pixel values at any zoom. HiDPI is separate and automatic.

The editor's entire interface is built with this module. See
[The editor](./editor.mdx).
