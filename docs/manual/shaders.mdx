# Shaders and materials

Shaders are [WESL](https://wesl-lang.dev): WGSL plus imports, `@if` variants
and dead-code elimination, linked to WGSL at run time. A `material` asset
names a shader and the values it draws with. `sprite`, `shape2d`, `shape3d`,
`mesh` and `tilemap` take one, a node can hand one to everything under it, and
a node with neither draws with the built-in material.

## A material and its shader

```toml
# materials/glow.toml
type = "material"
shader = "shaders/glow.wesl"

[params]
speed = 2.0
rings = 5.0
tint = "#ffb347"
```

```wgsl
// shaders/glow.wesl
import package::sprite::{VertexInput, VertexOutput, vertex, sample_albedo, tint, time};

struct Params { speed: f32, rings: f32, tint: vec4<f32> }
@group(3) @binding(0) var<uniform> params: Params;

@vertex fn vs_main(in: VertexInput) -> VertexOutput {
    return vertex(in);
}

@fragment fn fs_main(in: VertexOutput) -> @location(0) vec4<f32> {
    let uv: vec2<f32> = in.uv;
    let dist: f32 = length(uv - vec2<f32>(0.5, 0.5)) * 2.0;
    let wave: f32 = 0.5 + 0.5 * sin(dist * params.rings * 6.2832 - time() * params.speed);
    let ramp: vec4<f32> = params.tint * wave * wave;
    let albedo: vec4<f32> = sample_albedo(uv) * tint(in);
    return albedo + ramp * albedo.a;
}
```

| Import | What it binds |
| --- | --- |
| `package::sprite` | The 2D contract: frame and object uniforms, vertex inputs, `vertex` and `place`, `sample_albedo`, `tint`, `time` |
| `package::mesh` | The 3D contract, with `shade(in)` for the scene's lights and fog |
| `package::post` | A pass over the whole frame: `fullscreen`, `frame(uv)` and `texel()` |

A shader is its own two entry points and nothing else.

- `[params]` are the fields of the shader's `Params` struct, read off the
  linked shader rather than declared twice.
- A number is an `f32`, an array a `vec2`, `vec3` or `vec4`, a `#rrggbb`
  string a `vec4`.
- A param the shader does not read warns. One it declares and the material
  omits is zero.
- `[features]` are the `@if` flags that pick a variant at link time.
- A plugin can register shader modules a project's shader imports.

## A material for a whole subtree

The `material` component goes on any node, one that draws nothing included.
The node and everything under it draw with that material.

```toml
[[nodes]]
id = "rig"
name = "Rig"

[nodes.material]
source = "materials/metal.toml"
```

- The nearest one up wins, so a node under a second `material` takes that one.
- A renderable's own `material` is that node's alone and does not pass down.
  It is the split between `color` and `tint`, and Godot's `self_modulate` and
  `modulate`.
- `node.set_material(path)` sets it from a script. `node.material()` reads the
  node's own, and `node.global_material()` reads what it draws with.
- The contract a shader imports says which nodes it draws. A 3D material that
  reaches a 2D node leaves that node on the built-in material and warns once.
- In the inspector, an empty `material` field shows what the node inherits and
  from where, as `metal ← Rig`.

## A pass over the whole frame

A material named on [`camera.post`](./rendering.mdx#your-own-passes) is drawn over
the frame instead of over a node. It imports `package::post`, takes no mesh
and no texture of its own, and keeps its `Params` at `@group(1)`.

```wesl
import package::post::{PostInput, fullscreen, frame};

struct Params { amount: f32 }
@group(1) @binding(0) var<uniform> params: Params;

@vertex fn vs_main(@builtin(vertex_index) index: u32) -> PostInput {
    return fullscreen(index);
}

@fragment fn fs_main(in: PostInput) -> @location(0) vec4<f32> {
    let c: vec4<f32> = frame(in.uv);
    return vec4<f32>(mix(c.rgb, vec3<f32>(1.0) - c.rgb, params.amount), 1.0);
}
```

- `frame(uv)` is what the pass was handed: the film in linear light before
  `tonemap`, the finished picture after it.
- `texel()` is the size of one texel, for a pass that reads its neighbours.
- The same material may sit on both sides of `tonemap`. It is compiled once
  per side, because the two write different formats.

## In the editor

- The inspector lists a material's params off its linked shader, with an
  editor per type, and writes them back to the file.
- Its shader opens in the code editor highlighted as WESL. Save, and every
  material naming it relinks, and every node drawing with it is rebuilt.
- A shader that will not link says so in the Problems dock with the file, line
  and column the author wrote, and the node draws with the built-in material
  meanwhile. `render::check_material(path)` is the same answer for a tool.

Two ways to see what a shader is doing:

| Way | How |
| --- | --- |
| A line's value | Click a line number in the gutter and the viewport draws what that line computes for every pixel that reaches it: a `vec2` as red and green, an `f32` as grey, a `vec4` as colour. The line has to declare a value with its type written (`let dist: f32 = ...`) or a constructor. Click again to put the picture back |
| Channels | `render::set_channel("normals")` draws the scene's normals instead of its colour. `"uv"`, `"depth"` and `"albedo"` are the others, and `""` is the picture. The command palette has one command per channel |

## Determinism

- Rendering observes the simulation and feeds nothing back, so a shader is
  outside the digest, and `time()` is render time rather than the tick.
- A function marked `@const` runs on the CPU in headless tests, so the parts
  of a shader that are logic are still testable.
- A call to a name nothing declares fails to link rather than reaching a GPU.
