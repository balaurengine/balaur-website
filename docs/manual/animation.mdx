# Animation

One plugin, `balaur_anim`: one asset type (`animation_clip`), one component
(`animation`), one script module, one system. Tracks address properties
through the component registry. The plugin depends only on the core and
animates the renderer and the UI.

:::tip[For animators]

[Balaur for animators](/animate): bones, skinning, IK and the timeline, on the rig that ships in the game.

:::

## Clips

A clip is a length, an end mode (`none | loop | pingpong`) and a list of
tracks. It lives in its own file, inline in the scene node, or in a library
file under `[clips.<name>]`, addressed `file.toml#name`.

```toml
# animations/platform.toml
type = "animation_clip"

[clips.patrol]
length = 4.0
loop = "pingpong"

[[clips.patrol.tracks]]
property = "position"      # position | rotation_euler | rotation | scale | <component>/<property>
interp = "linear"          # step | linear | cubic
keys = [
  { t = 0.0, value = [-2.5, 0.25, -2.0] },
  { t = 4.0, value = [-2.5, 0.25, 2.0], ease = "in_out_sine" },
]

[[clips.patrol.tracks]]
keys = [{ t = 4.0, call = "on_reached_end" }]   # a method track
```

```toml
# in the scene
[nodes.animation]
library = "animations/platform.toml"
autoplay = "patrol"
```

- A track drives the transform or any registered component property:
  `shape3d/color`, `shape2d/radius`, `widget/x`, third-party components
  included.
- A track with no `property` is a method track, calling a method on the node's
  script.
- Rotation keys are authored as euler radians and interpolated as quaternions.
  A `rotation` track takes the quaternion itself; an imported model's clips
  use it.

## The script module

```rune
animation::play(this.node, "hop", #{ speed: 1.0 });
animation::pause(this.node);   // resume continues; stop ends
animation::queue(this.node, "wave");

pub fn on_reached_end(this) {   // called by the clip's method track
    // ...
}
```

Also `seek`, `time`, `current`, `is_playing`, `just_finished`, and `define`,
which builds a clip from an object at run time. `is_tween_running(handle)`
answers for a tween.

## Tweens

A clip generated from the node's current values, run through the same sampler
and fixed step.

```rune
animation::tween(this.node, #{
    steps: [
        #{ property: "position", to: [0.0, 3.0, 0.0], duration: 0.5, ease: "out_back" },
        #{ property: "shape3d/color", to: [1.0, 0.0, 0.0, 1.0], duration: 0.5, parallel: true },
        #{ call: "on_landed" },
    ],
});

animation::tween_to(this.node, "position", [0.0, 9.0, 0.0], 0.2, "linear");   // the one-step shorthand
```

| Key | What it does |
| --- | --- |
| `to`, `by`, `from` | absolute, relative, explicit start |
| `target` | tween another node |
| `parallel` | join this step to the one before it |
| `interval`, `call` | sequence among the property steps |

- Steps run in order.
- The spec is data: it serialises, the editor authors one, and it hot reloads.
- Easing is twelve transitions in four modes, with Godot's names and shapes.

## Skeletons and skins

A bone is a node with a rest pose: `bone2d` in 2D, `bone3d` in 3D. A skin is a
`polygon`: a textured 2D polygon whose mesh carries bone weights. A clip on
the character keys its bones by path.

```toml
[[nodes]]
name = "Thigh"
parent = "n_hip"
transform = { position = [0, 0.85, 0] }
bone2d = { rest_position = [0, 0.85], rest_rotation = 0.0 }

[nodes.polygon]                       # on a sibling node
texture = "art/limb.png"
skeleton = ".."                       # the rig root; bones are its descendants

[nodes.polygon.mesh]                  # a `mesh` asset, inline
positions = [[-0.4, 0], [0.4, 0], [0.4, 0.85], [-0.4, 0.85]]
[[nodes.polygon.mesh.skin.bones]]
path = "Hip/Thigh"
weights = [0, 0, 1, 1]
```

- The outline is ear-clipped. `internal` vertices and hand-drawn `polygons`
  control the triangulation.
- UVs default to the texture centred on the node at `pixels_per_unit`.
- Skinning runs on the GPU from a joint palette computed off the scene tree. A
  headless run computes the same palette; bones are in the determinism digest.
- `skeleton::apply_rest(node)`, `skeleton::overwrite_rest(node)` and
  `skeleton::bones(node)` are the whole module.

![A polygon's inspector: vertices, drawn polygons, bones and brush](/img/editor/component_limb.webp)

### Tools

| Tool | What it does |
| --- | --- |
| Rig bone | Bones as diamonds in 2D and octahedra in 3D: click to select, drag to pose, *+ bone* grows a child from the selection |
| Polygon · Points | Outline and internal vertices |
| Polygon · Polygons | The triangulation by hand |
| Polygon · UV | The points placed over the texture |
| Polygon · Weights | Bone influence painted with a brush |

The polygon stays skinned during editing. The inspector's Skeleton section
has the two rest-pose verbs.

### Modifiers

A `modifier2d` runs after the clip every frame. `modifier3d` is the same six
kinds over `bone3d`.

| `kind` | What it does |
| --- | --- |
| `look_at` | Turns one bone so it points at a target node. |
| `two_bone_ik` | Bends a root, middle and tip chain so the tip reaches the target; `flip` picks the bend side. |
| `fabrik` | Reaches with a chain of any length. Converges from any pose. `iterations`, `tolerance`. |
| `ccdik` | The same reach, one bone at a time. The only kind with an `angle_limit` per bone. |
| `jiggle` | No target: a spring per bone toward the clip's pose. `stiffness`, `damping`, `mass`, `gravity`, `use_gravity`. |
| `follow` | Moves the node itself to its target plus `offset`, `lag` seconds behind. Closes the same share of the gap on every fixed tick. |

`chain` says how many bones a chain solver walks, counting the driven one.
Zero walks to the deepest tip.

```toml
[nodes.modifier2d]
kind = "two_bone_ik"
bone = "Shoulder"
target = "Target"
```

`follow` drives the node itself. Its state is the node's transform. A rollback
restores a follower from the snapshot.

```toml
# A camera that trails the player a fifth of a second behind.
[nodes.modifier3d]
kind = "follow"
target = "../Player"
lag = 0.2
offset = [0, 3, 8]
```

```toml
# The plume in examples/rig: nothing keys it, and it moves anyway.
[nodes.modifier2d]
kind = "jiggle"
bone = "Hip/Thigh/Shin/Plume"
stiffness = 26.0
damping = 0.32
use_gravity = true
```

![The Rig tool drawing a modifier's chain, the dashed line to its target and the handle that drags it](/img/manual/rigging_modifiers.webp)

The viewport draws the chain a modifier solves, a dashed line to the target
and a handle that drags the target node. A `chain` of two draws two bones.

### Free-form deformation

A `polygon/deform` track keys an `[dx, dy]` offset per vertex, added to the
authored positions before skinning: a mouth, a cape edge or a breathing
outline. Spine calls it free-form deformation.

```toml
[[tracks]]
target = "Limb"
property = "polygon/deform"
keys = [
  { t = 0.0, value = [0, 0, 0, 0] },
  { t = 1.0, value = [-0.09, 0, 0.09, 0], ease = "in_out_sine" },
]
```

- The one track with more than four numbers per key.
- In Points mode with the Animate persona armed, dragging a vertex moves the
  offset.
- The inspector's **Deform · key** row writes it at the playhead.

### Retargeting

A `bone_map` asset pairs canonical bone names with one rig's node paths. A
clip authored for a different skeleton plays through it.

```toml
type = "bone_map"

[bones]
Hips = "Armature/Hips"
Spine = "Armature/Hips/Spine"
```

```rune
animation::play(hero, "walk", #{ "retarget": "animations/hero.bonemap.toml" });
```

- Each track's target is renamed through the map before the pose is written.
- A rotation key is read as a turn away from the profile's rest and applied to
  this rig's.
- A position key is scaled by how much longer this rig's bone rests.
- A track the map does not name keeps its authored path.
- `skeleton_profile` names the canonical skeleton. Leaving it out uses the
  built-in humanoid.

![The Bone map dock: canonical names on the left, the rig's own bones on the right](/img/manual/rigging_bonemap.webp)

The Bone map dock fills rows by name and writes the asset. Matching ignores
case, separators and an exporter's prefix: `LeftUpperArm` finds
`mixamorig:LeftUpperArm`.

### Weights, mirroring and tracing

![The Weights dock over a skinned polygon](/img/manual/rigging_weights.webp)

| Verb | What it does |
| --- | --- |
| Weights dock | Picked vertices, one editable weight per bone, a per-vertex sum that goes red when it is not one |
| Bind, Unbind, Normalise | On the picked vertices |
| Auto | Weights by distance to each bone's segment |
| Smooth | Average with the vertices sharing an edge |
| Mirror (Rig) | Reflects every bone's rest over x or y, and hands each rest to the bone whose name differs by a side: `Arm_L` to `Arm_R`, `left_hand` to `right_hand` |
| Mirror (Polygon) | Reflects the picked vertices and swaps the weights the same way |
| Trace | Walks a texture's alpha at a threshold and writes the outline as points, simplified to a tolerance in pixels |

### Ragdolls

`physics2d.ragdoll(node, opts)` walks a rig into a body and a capsule per
bone, hinged to its parent's, and leaves a `ragdoll` component.

```rune
physics2d::ragdoll(this.node, #{ blend: 0.0, thickness: 0.22, limits: [-0.7, 0.7] });
// … and later, to fall over:
physics::ragdoll_blend(this.node, 1.0);
```

- `blend` moves each bone from the pose the clip wrote toward its body's.
- At `0` the clip drives and the bodies simulate unseen. At `1` the rig is
  limp.
- The bodies are nodes with `body2d`, `collider2d` and `joint2d`:
  inspectable, undoable and saved with the scene.
- The editor's **Skeleton · Ragdoll** row is this call, and
  `physics3d.ragdoll` is the 3D twin.

### 3D rigs

```bash
balaur import model.glb --project my-game
```

- Copies the model under `models/`, writes its joint hierarchy as a scene with
  `bone3d` rest poses and one `mesh` node, and its animations as a clip
  library. All TOML.
- A `.gltf` with its `.bin` and textures beside it imports the same way.
- The mesh is skinned every frame from the scene tree. The same clips, rest
  verbs and bone gizmos apply.
- The joint palette goes to a vertex shader. A 3D rig deforms on the GPU; the
  mesh's buffers are untouched.
- A node naming a `material` asset, or a frame under a shader channel view,
  uses the CPU path: those shaders draw against `package::mesh`. The shader's
  blend is `@const`. A headless test checks it against the CPU reference.

![The column of examples/rig3d bent by its sway clip, its three bones deforming the imported mesh](/img/manual/animation_gpu_skinning.webp)

`examples/rig` is one figure with four kinds of rigging: a clip keying bone
rotations, two-bone IK reaching a moving target, a `jiggle` plume, and a
`polygon/deform` breathing outline. It falls into a ragdoll every few seconds.
`examples/rig3d` is an imported column.

## Determinism and scheduling

- Playback advances on its own fixed 1/60 accumulator.
- Every transcendental (easing, euler to quaternion, slerp) runs on `libm`,
  bit-identical on every platform.
- The system runs after the script tick. `animation::play()` takes effect the
  same frame.
- It runs before physics reads transforms. An animated kinematic platform
  pushes what stands on it (`examples/hello`).
