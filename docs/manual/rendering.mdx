# Rendering

A 2D scene draws unlit until it has a `light2d`. One `light2d` starts a light
map at the camera's resolution. Everything drawn is multiplied by that map
plus the camera's `ambient`. Sprites, polygons and tile maps are lit with no
material.

![A warm point light and a cool fill light over a backdrop, a rect and a circle occluder each casting a shadow away from the warm light, and the rest of the frame fallen to a dark ambient](/img/manual/rendering_lights2d.webp)

## A light

```toml
[[nodes]]
id = "n_lamp"
name = "Lamp"

[nodes.transform]
position = [0, 2.5, 0]

[nodes.light2d]
kind = "point"          # point | directional
color = "#ffd28a"
radius = 8.0            # world units; a point light fades to nothing here
intensity = 1.6
shadows = true
```

- The node's `transform` places a light and its rotation aims it. At rest a
  `light2d` shines along −y; the node's z rotation turns it.
- A point light fades quadratically to zero at `radius`.
- A directional light ignores `radius` and lights the whole view.
- `intensity` above 1 pushes past white, which [bloom](#post-processing)
  picks up.

## Ambient

```toml
[nodes.camera]
kind = "2d"
zoom = 60.0
ambient = "#181c22"     # what an unlit surface is multiplied by
```

- A scene with no `light2d` costs no extra pass and no extra draw.
- With a light, everything the lights do not reach falls to the camera's
  `ambient`, black by default.
- White `ambient` is the unlit look.

## Occluders and shadows

```toml
[nodes.occluder2d]
# mesh = "meshes/wall.toml"   # points in order; empty derives the outline
# closed = true               # the last point joins the first
```

- A light with `shadows = true` is blocked by any node with an `occluder2d`.
  Each edge is extruded away from the light into a polygon that masks the
  light.
- Left empty, the outline follows the node's `collider2d`, else its circle,
  capsule, rect or sprite shape.
- `mesh` names an outline of its own. A polyline or polygon node needs one.
- Every edge casts, so an occluder stands in its own shadow. A crate that
  should stay lit needs a smaller outline than its sprite, or a light with
  `shadows = false`.
- A directional light's shadows are parallel.

![Three occluders under one directional light, each casting a parallel shadow strip at the light's angle: a rect, a circle and a capsule, their outlines traced faithfully](/img/manual/rendering_directional.webp)

![The editor with an occluder node selected: only the Points mode chip, an Occluder section in the inspector, and the light gizmos over the lit scene](/img/manual/rendering_occluder_tool.webp)

- The Polygon tool traces an `occluder2d` in Points mode. Triangles, UVs and
  weights modes are not offered.
- The Lights chip in the Scene persona draws every light's reach and every
  occluder's resolved outline, derived ones included.

## Post-processing

```toml
[nodes.camera]
kind = "2d"
post = ["bloom"]
bloom_threshold = 0.9   # brightness a pixel has to pass
bloom_intensity = 0.7   # how much is added back
```

- `bloom` is the one that applies in 2D; the light map gives it bright pixels
  to bleed.
- `ssao`, `ssr` and `dof` are the other three, 3D only.
- `post` spans both dimensions (`ambient` does not). The last current camera
  of either kind sets it.

### Custom passes

`post` runs in list order. An unknown name is a `material` drawn over the
whole frame.

```toml
[nodes.camera]
post = ["fog", "tonemap", "bloom", "materials/grade.toml"]
```

- The engine's own passes run at fixed points: `ssao` and `ssr` feed shading,
  `bloom` rides the tonemap. Naming one switches it on.
- Order applies to materials. Before `tonemap` a pass reads linear light and
  its output blooms. After it a pass reads the tonemapped picture.
- A list without `tonemap` has it at the head: a plain list of materials runs
  over the finished frame.
- A pass that fails to compile is reported and left out.

See [Shaders](./shaders.mdx#a-pass-over-the-whole-frame) for what a post
material imports.

## Light map coverage

- The multiply covers sprites, polygons, tile maps, and a 3D scene under a 2D
  one.
- Debug lines and particles draw after it and stay unlit.
- Lights never touch the simulation. A lit game and a headless one tick
  identically.

## Lights in 3D

```toml
[[nodes]]
name = "Key"

[nodes.transform]
position = [4, 7, 4]
rotation_euler = [-0.87266, 0.69813, 0]   # radians: -50° and 40°

[nodes.light3d]
kind = "spot"
color = "#fff2e0"
intensity = 6
radius = 30
inner = 25
outer = 45
```

![A spot light selected in the editor, its cone drawn in the viewport and its light3d rows in the inspector](/img/manual/editor_lights.webp)

- The node's `transform` places it and its rotation aims it. `kind` is
  `directional`, `point` or `spot`.
- A scene with no `light3d` keeps the engine's default key light. The first
  `light3d` replaces it.
- `visible` on the node turns it off.
- `shadows` says whether it casts. `layers` is a bitmask; a `mesh` or
  `shape3d` is lit when it shares a bit.

## The scene's atmosphere

```toml
[nodes.environment]
sky = "skies/studio.hdr"
ambient = "#20242a"
tonemap = "neutral"
exposure = 1.1
fog = "exponential"
fog_color = "#9fb4c8"
fog_density = 0.012
```

- `environment` carries scene-wide settings: sky, ambient light, fog,
  exposure, tonemap, colour grading, shadow budget.
- The last `current` one in tree order wins.
- `sky` is a project-relative equirectangular image: `.hdr`, `.exr` or `.png`.
  It draws behind the scene. `show_sky` hides it; orientation and intensity
  still apply.
- Image-based lighting from the sky is not bound yet. A scene is lit by its
  `light3d` nodes and its ambient.
- The editor's Library dock ships three gradient skies.

## A physically based material

A 3D material imports `package::pbr` for metallic, roughness, emissive and
reflectance. The default is Lambert.

```wgsl
import package::mesh::{VertexInput, VertexOutput, vertex};
import package::pbr::{default_surface, shade_pbr};

struct Params { metallic: f32, roughness: f32, reflectance: f32 }
@group(3) @binding(0) var<uniform> params: Params;

@fragment fn fs_main(in: VertexOutput) -> @location(0) vec4<f32> {
    var s = default_surface(in);
    s.metallic = params.metallic;
    s.roughness = max(params.roughness, 0.045);
    s.reflectance = params.reflectance;
    return shade_pbr(in, s);
}
```

- A `[params]` key named for one of six texture slots and given an image path
  binds that slot: `albedo`, `normal`, `metallic_roughness`, `occlusion`,
  `emissive`, `height`.
- A slot left out gets a one-pixel neutral texture.
- The editor's library ships four materials over one such shader.

## Limits

- A frame draws at most 64 2D lights. Each shadow-casting one costs a pass.
- A scene past that is told once in the log.
- The 3D contract carries sixteen lights in its frame uniforms.
