# Scripting

Scripts are [Rune](https://rune-rs.github.io/): `.rn` files attached to nodes
in a scene. Rune reads like Rust without types, and the
[Rune book](https://rune-rs.github.io/book/) covers the language itself.

## The model

```rune
// scripts/spinner.rn
pub fn init(this) {
    this.angle = 0.0;
}

pub fn update(this, dt) {
    this.angle += dt;
    this.node.transform.rotation_euler = [0.0, this.angle, 0.0];
}

pub fn fixed_update(this, dt) {}   // the fixed 60 Hz step, before physics
pub fn draw_ui(this) {}            // immediate-mode UI, once per frame
```

| Hook | When |
| --- | --- |
| `init` | once, after the properties are written |
| `update(dt)` | once a frame, with the measured frame time |
| `fixed_update(dt)` | on the fixed 60 Hz step, before physics. Simulation belongs here |
| `draw_ui` | once a frame, immediate mode |
| `on_free`, `hot_reload` | teardown, and a state migration after a save |

- One instance per attached node, handed back as `this`, with the owning node
  on `this.node`.
- Rune mutates an object in place, so what a script writes to `this` is what
  the host reads next frame.
- `project.toml` names the language with `language`. It defaults to `"rune"`,
  and any other value is an error.
- See [Determinism](./determinism.mdx) for what belongs in which hook.

## Exported properties

```rust
pub fn exports() {
    #{ speed: 2.0, clockwise: true }
}
```

```toml
[nodes.script]
source = "scripts/spinner.rn"

[nodes.script.props]
speed = 3.5
```

- Defaults are written onto the instance, the node's `props` over them, and
  only then is `init` called.
- The inspector writes an override only where the value differs from the
  default, so changing a default reaches every node that never overrode it.
- `node.attach_script(path, props)` is the same thing at run time.

## Modules

Subsystems declare their bindings once against a language-neutral seam
(`balaur_script`), and scripts reach them with `::`.

```rune
let t = engine::time();
let ball = scene::get_node("World/Ball");
physics3d::add_body(this.node, physics3d::BODY_DYNAMIC);
```

`engine`, `scene`, `log`, `input`, `rng`, `math`, `physics`, `physics2d`,
`physics3d`, `render`, `audio`, `ui`, `animation`, `skeleton`, `assets`,
`http`, `websocket`, `gamend`, `events`, `task`, `debugger`, `fs`, `toml`,
`json`, `script`. Every function and constant is in the
[script modules reference](/docs/reference/modules), generated from a booted
engine so it cannot drift.

| Shape | Example |
| --- | --- |
| Named values, never spelled | `input::KEY_SPACE`, `physics3d::BODY_DYNAMIC`, `ui::ANCHOR_TOP_LEFT` |
| Node operations are methods | `node.get_node("../Target")`, `node.queue_free()` |
| Several returns are a tuple | `let (text, changed) = ui::text_field(...)` |
| A vector is one value with fields | `this.node.transform.position.y` |
| Tables, lists, nothing | `#{ kind: "ball" }`, `[1, 2]`, `()` |
| Integers and floats never mix | a float argument is written `0.0` |

Each component a node can carry is a field on the node, and that field is a
handle whose methods are the driving module's functions with the node filled
in. `this.node.body2d.apply_impulse(x, y)` is
`physics2d::apply_impulse(this.node, x, y)`. Every handle also answers `get()`,
`set(table)`, `has()` and `remove()`; the
[component reference](/docs/reference/components) lists the methods per
component.

```rune
let body = this.node.body2d;
body.apply_impulse(0.0, 12.0);
if body.linear_velocity().0 > 5.0 {
    body.set_linear_velocity(5.0, 0.0);
}
```

A handle's properties are fields too. The transform is a component like the
rest, so a script moves a node by writing its `transform`:

```rune
let p = this.node.transform.position;                // p.x, p.y, p.z
this.node.transform.position = [p.x, p.y + 1.0, p.z];
this.node.transform.rotation_euler = [0.0, math::rad(90.0), 0.0];
```

- Rotations are euler radians, x then y then z. Only the inspector shows
  degrees.
- A node without a `transform` sits where its parent is. Writing one gives it
  one.
- `position()`, `set_position(x, y, z)`, `translate` and `rotation_degrees`
  stay on the node as short forms. `global_position()` answers in world space.

## Script files as modules

```rune
mod util;   // scripts/util.rn

pub fn update(this, dt) {
    this.speed = util::clamp(this.speed + dt, 0.0, 10.0);
}
```

- `mod name;` pulls in `name.rn` beside it: from disk in a dev run, from the
  pack when shipped. Its items are reached as `name::item`.
- `script::require("lib.rn")` loads a file at run time and returns its
  functions in an object.
- Both hot reload in place. A module object held since `init` sees the new
  code after a save.

## Errors

A binding that fails raises, and the call ends there. `script::attempt`
returns `(ok, value)`: the result, or the error message.

```rune
let (ok, clip) = script::attempt(|| assets::load("animations/missing.toml"));
if !ok {
    log::warn(format!("no clip: {}", clip));
}
```

## Tooling

The engine knows its own API, so it can answer what completes at a caret.
`script::complete`, `hover`, `signature`, `definition`, `symbols`,
`references`, `find`, `rename`, `replace` and `format` are those answers. Two
clients read them: the editor's Script persona, and `balaur lsp`, which speaks
the Language Server Protocol on stdin and stdout.

![The completion popup: a module path, and the functions and constants under it](/img/manual/script_completion.webp)

| After the caret | What completes |
| --- | --- |
| `physics2d::` | that module's functions and constants, each with the line the [reference](../reference/index.md) prints |
| `node.body2d.` | what acts on that component, plus `get`, `set`, `has`, `add`, `remove`, `props` |
| `this.` | the script's own `exports()` properties and its `pub fn`s |
| anything else | component names, `node`'s methods, Rune's own, this file's functions, its locals, keywords |

| Key | What it does |
| --- | --- |
| `⌘B` | Go to definition. A project `pub fn` opens its file; engine API opens the Docs dock, since there is no file to land in |
| `⌥⇧F` | Format the buffer with Rune's own formatter |
| `⌘⇧R` | Rename an identifier |
| `⌘⇧F` | Replace text |

Rename and replace are textual. Rune keeps no cross-file index, so both walk
the files a script's `mod` declarations reach and list every match before
writing. A rename matches the identifier as a token; a replace matches text.

```bash
balaur fmt .           # lay every script out
balaur fmt . --check   # name the files that would change; exits 1 if any do
```

`balaur lsp <project>` gives another editor the same answers: diagnostics,
completion, hover, signature help, go-to-definition, document and workspace
symbols, references, rename and formatting. The engine repository ships a VS
Code extension in `editors/code`, whose README carries the Neovim and Zed
recipes.

## Events

No `connect`-style signals. The engine calls methods a script declares by
name, so a handler reads like `update(dt)`.

- `on_animation_finished(name)` from an animation, `on_click` from a widget,
  `on_response(r)` from an HTTP request.
- Most events have a polling twin (`input::just_pressed`,
  `animation::just_finished`). An event is a frame-scoped snapshot, not a
  subscription.

An `async` entry point suspends on `task::wait` and resumes when the result
enters the simulation at the start of a later tick. See
[Networking](./networking.mdx) for the delivery model.

```rune
pub async fn init(this) {
    let r = task::wait(http::request("https://example.com")).await;
    log::info(format!("{} {}", r["status"], r["body"]));
}
```

Two ways for scripts to reach each other:

| Shape | Call |
| --- | --- |
| One target, now, when you hold the node | `node.call("method", args...)` |
| Something happened, and the emitter does not know who cares | `events` |

```rune
this.node.emit("hit", #{ damage: 3 });          // from this node

events::subscribe(this.node, "hit", enemy);     // only that enemy's
events::subscribe(this.node, "hit");            // every emitter's
pub fn on_hit(this, payload) {}                 // on_<name>, whichever it was
```

- Delivery is the top of the next frame's update, in emission then
  subscription order, so a handler never runs inside the call that emitted.
- The emitter is part of the key, so a hundred emitters of `hit` do not wake a
  hundred handlers each: delivery is a lookup.
- `events::emit` is the same without an emitter. `events::emitted(name)` and
  `events::emitted_from(node, name)` are the polling twins.

## Hot reload

<Clip name="scripting_live" alt="A value changed and saved while the scene runs, then a breakpoint stepped in the Debugger dock" />

- The host watches the project directory and recompiles a file on save.
- Rune compiles to an immutable unit, so nothing is patched: the new unit
  replaces the old, instances keep their state objects, and the next call
  resolves against the new code.
- Save-to-live latency is file-watcher latency, a few milliseconds.
- `hot_reload(this)` lets a script migrate the shape of its state.
- A save that does not compile puts the compiler's own diagnostic (file, line,
  column, caret) in the Output dock, and the previously compiled code keeps
  running.
- Module paths resolve at compile time, so a misspelled engine call is caught
  on save rather than when the line finally runs.

## Debugging

Click a line number in the Script persona to set a breakpoint and run the
scene. The Debugger dock shows call frames and their locals.

| Control | Key |
| --- | --- |
| Continue | `F5` |
| Step over, into, out | `F10`, `F11`, `Shift+F11` |

The same controls are the `debugger` module, so a tool can drive them:

```rune
debugger::set_breakpoints("scripts/ball.rn", [12, 30]);
let pause = debugger::paused();         // (), or the pause: reason, line, frames
debugger::resume(debugger::STEP_OVER);  // CONTINUE | STEP_OVER | STEP_INTO | STEP_OUT
```

```rune
debugger::set_break_on_error(true);
```

- A script that throws logs the error and the engine carries on. Break on
  error stops at the line that threw, with frames and locals still readable.
- It is off by default, because it puts every synchronous call through the
  stepping executor, otherwise used only where a breakpoint is set. The
  Debugger dock has the same switch.
- An error pause cannot be continued. The call is over, so any step button
  drops it and finishes the tick it interrupted.
- An async entry point runs as a future and cannot be paused, so a breakpoint
  inside one is let through.
- Locals are a frame's named arguments, since Rune keeps no names for its
  other slots.

## Determinism in scripts

- `math` (`math::sin`, `math::pow`, `math::PI`, …) is `libm`-backed and
  bit-identical everywhere.
- `rng` is an engine-owned seeded stream.
- Simulation goes in `fixed_update`. See [Determinism](./determinism.mdx) for
  the rules.
