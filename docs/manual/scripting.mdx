# Scripting

## The model

A script declares lifecycle functions — `init`, `update(dt)`,
`fixed_update(dt)`, `draw_ui`, `on_free`, `hot_reload` — and gets one
instance per attached node, with the owning node available on the instance.
`update` runs once per frame with the measured frame time; `fixed_update`
runs on the fixed 60 Hz step, before physics, and is where simulation
belongs.

In Luau, a `.luau` file returns a class table; each instance is a table whose
metatable indexes it, and the node is `self.node`. In Rune, a `.rn` file
declares free functions taking the instance first (`pub fn update(this, dt)`),
and the node is `this.node`.

A project picks its language with `language` in `project.toml`; absent means
Luau. `language = "mixed"` runs both hosts side by side, routing each file by
extension — `.luau` on the Luau host, `.rn` on Rune — with a fixed fan-out
order, so a mixed project stays as deterministic as a single-language one.

## Modules

Scripts see the same modules in both languages, because subsystems declare
their bindings once against a language-neutral seam: `node`, `engine`,
`scene`, `log`, `input`, `rng`, `math`, `physics`, `physics2d`,
`physics3d`, `render`, `audio`, `ui`, `animation`, `skeleton`, `assets`,
`http`, `websocket`, `gamend`, `task`, `debugger`, `fs`, `toml`, and
`json`. The complete surface — every function and constant — is in the
[script API reference](../reference/script-api.md), which is generated from
a booted engine so it cannot drift.

Values a binding accepts are named rather than spelled: `input.KEY_SPACE`,
`input.MOUSE_LEFT`, `physics3d.BODY_DYNAMIC`, `ui.ANCHOR_TOP_LEFT`.

Some calls return several values — `local text, changed = ui.text_field(...)`
— while a vector is one value and arrives as a table, indexed or unpacked:
`local x, y, z = table.unpack(node:position())`.

`require` works in both languages, with in-place module hot reload.

## Events

There are no `connect`-style signals. The engine calls methods a script
declares by name — `on_animation_finished(name)` from an animation, a
widget's `on_click`, `on_response(r)` from an HTTP request — so a handler
reads exactly like `update(dt)` does. Most events also have a polling twin
(`input.just_pressed`, `animation.just_finished`): an event is a frame-scoped
snapshot, not a subscription.

Asynchronous operations can also be awaited sequentially —
`local r = await(http.request(url))` in Luau,
`task::wait(http::request(url)).await` in Rune — with the script suspending
until the result enters the simulation at the start of a later tick. See
[Networking](./networking.mdx) for the delivery model.

Scripts invoke each other the same way the engine does:
`node:call("method", ...)` calls a method on another node's script instance
by name — including across languages in a mixed project, because the seam
moves names and neutral values, never live code.

## Hot reload

The host watches the project directory. On save, in Luau:

1. The file is recompiled with the Luau compiler. A compile error keeps the
   old class running and is reported once.
2. The new chunk is evaluated into a fresh class table.
3. The contents of the existing class table are swapped in place.

Because instances reference the class only through their metatable, every
live instance sees the new code immediately while `self` state survives
untouched. The swap is O(class size) — microseconds in practice; measured
save-to-live latency is file-watcher latency, a few milliseconds. The
optional `hot_reload` hook lets scripts migrate state shapes.

Rune compiles to an immutable unit, so the new unit replaces the old one;
instances keep their state objects, and the next call resolves against the
new code.

## Debugging

Luau scripts can be paused on a breakpoint and stepped. The editor's Script
persona sets breakpoints in the gutter and steps with `F5` (run), `F10`
(over), `F11` (into) and `Shift+F11` (out); the Debugger dock shows the call
frames and their named locals. The same controls are a script module, so a
tool can drive them:

```lua
debugger.set_breakpoints("scripts/ball.luau", { 12, 30 })
local pause = debugger.paused()          -- nil, or the frame the VM stopped in
debugger.resume(debugger.STEP_OVER)      -- CONTINUE | STEP_OVER | STEP_INTO | STEP_OUT
```

## Determinism in scripts

The scripting environment is set up so that straightforward simulation code
is deterministic by construction: `math.sin`, `math.cos`, and the rest are
rebound to bit-identical pure-Rust implementations, and `math.random` is
backed by an engine-owned seeded PCG32 stream (also exposed as the `rng`
module). See [Determinism](./determinism.mdx) for the full picture and the
rules simulation code should follow.
