# Modules and extensions

Everything above the core is a plugin, and a plugin ships one of two ways
from the same source:

- A **module** is linked into the engine and switched on by a cargo feature —
  `audio`, `net`, and `gamend` work this way (all on by default; switching
  one off drops its entire dependency stack from the binary).
- An **extension** is the same `Plugin` trait built as a shared library
  (`cdylib`) and loaded at run time from the project's `extensions/`
  directory, with the `extensions` feature enabled.

One trait, so the same source ships either way.

## Writing a plugin

A plugin declares a manifest and registers what it needs — resources, script
modules, functions, constants, components, asset types:

```rust
impl Plugin for Greeter {
    fn manifest(&self) -> &Manifest {
        &self.manifest
    }

    fn declare(&mut self, reg: &mut Registry<'_>) -> anyhow::Result<()> {
        reg.insert_resource(GreetingCount(0));
        let mut m = reg.script_module("greeter")?;
        m.function("greet", |eng: &Engine, name: String| {
            eng.resource::<GreetingCount>().borrow_mut().0 += 1;
            Ok(format!("hello, {name}"))
        });
        Ok(())
    }
}
```

Scripts then call `greeter.greet("...")` like any built-in module, in either
language. `examples/extension_greeter` in the repository is the complete
working example.

## Rust or C at the boundary

Rust has no stable ABI, so an extension comes in one of two shapes, picked by
which symbols the library exports:

| | Rust extension | C extension |
| --- | --- | --- |
| Crosses the boundary | Full Rust types | `#[repr(C)]` types only |
| Checked by | Compiler + engine version + registry ABI fingerprint | One ABI version number |
| Written in | Rust, with the exact compiler that built the host | Anything with a C ABI: C, Zig, Odin, C++ |

The Rust path is refused unless the extension's fingerprint matches the
host's exactly — checked through a fixed-size tag *before* anything
Rust-shaped crosses, so a mismatched build fails with a message naming the
differences rather than crashing later.

The C path keeps its state behind its own pointer and receives a table of
host function pointers; no allocation crosses the boundary, and the committed
C header is asserted against the Rust layout from both sides. Today it
covers script modules of functions and constants.

Extensions load in an order sorted by name and declared requirements — never
by directory iteration — because load order decides registration order,
which decides the simulation.

For the binding API itself — declaring functions, registering components and
scene keys — see [Architecture](../architecture.mdx); `balaur_physics` is
the reference implementation of a full plugin.
