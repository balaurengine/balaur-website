# Physics

Physics is a plugin wrapping [Rapier](https://rapier.rs): rapier3d for the
`body3d` / `collider3d` components, rapier2d for `body2d` / `collider2d`. The two
worlds live side by side over the same scene tree, and both are built with
Rapier's `enhanced-determinism` feature and stepped on a fixed 60 Hz
accumulator.

## Declaring bodies

In a scene file:

```toml
[[nodes]]
name = "Crate"
position = [0, 3, 0]
body3d = "dynamic"                 # dynamic | kinematic | static
collider3d = { kind = "cuboid", half_extents = [0.5, 0.5, 0.5] }
```

Colliders take `kind` (`ball` / `cuboid` in 3D, `circle` / `rect` in 2D, and a
dozen more each) with the matching dimensions, plus `restitution`, `friction`,
and `density`.

Or from a script, with the same vocabulary:

```rune
physics3d::add_body(this.node, physics3d::BODY_DYNAMIC);
physics3d::add_ball_collider(this.node, 0.5);

physics2d::add_body(this.node, physics2d::BODY_DYNAMIC);
physics2d::add_collider(this.node, #{ kind: physics2d::SHAPE_RECT, half_extents: [0.5, 0.5] });
```

## Two ways to call, one function

Every function above takes the node as its first argument, so it is also a
method on the node's component handle. These two lines are the same call:

```rune
physics2d::apply_impulse(this.node, 1.0, 0.0);
this.node.body2d.apply_impulse(1.0, 0.0);
```

`node.body2d` binds the node to whichever module drives that component, which
is how the dimension stops being something you repeat: the same
`apply_impulse` on a `body3d` handle reaches `physics3d`. Handles also carry
`get()`, `set(table)`, `has()` and `remove()`, so `this.node.body3d.get()`
hands back the component's properties as a table. A method no module declared
for that component is an error naming it — `node.sprite.apply_impulse` does
not silently do nothing.

Which methods a component has is listed on its reference page, for example
[`body2d`](/docs/reference/components/body2d).

## Driving the simulation

Bodies, colliders, joints, velocities and queries live in `physics3d` and
`physics2d` — one module per world, mirroring the `body3d` / `body2d` split.
`physics2d` adds `max_contact_impulse(node)`, the strongest impact a body took
this frame, for impact-driven gameplay such as destruction or damage.

The `physics` module holds only what spans both worlds at once: `set_paused`,
`is_paused`, `clear`, `set_sleeping_allowed`, `sleeping_allowed`, the debug
draw, and the solver's tuning and counters. Tools can therefore treat
"physics" as one simulation — the editor pauses it until play, and its
Physics persona draws every body's collider and centre of mass over the
scene, playing or not.

The full function lists are in the
[script modules reference](/docs/reference/modules).

## Determinism

Physics steps on a fixed 60 Hz accumulator, never on the variable frame
delta, and iterates order-sensitive collections deterministically. Two runs
with identical inputs match bit for bit, and a test in the repository asserts
it. See [Determinism](./determinism.mdx).
