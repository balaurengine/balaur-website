# Introduction

Balaur is a scriptable, node-based game engine with a Rust data plane.

From a game developer's perspective, Balaur looks like Godot: a scene tree of
named nodes, with scripts attached to them. Under the hood, every node is an
ECS entity, every subsystem (physics, rendering, audio, input, UI) is a plugin
over the same data plane, and the editor is itself a Balaur project.

:::warning

There is no binary release yet. Balaur builds from source with a Rust
toolchain; see [Getting started](./getting-started.mdx).

:::

Two features are load-bearing and non-negotiable:

- **Instant hot reload.** Saving a script swaps its code into the running game
  in milliseconds, preserving all live state. It is automatic, always on in
  dev mode, and provided by the core, not by frameworks or per-game glue.
- **Cross-platform determinism.** Identical inputs produce bit-for-bit
  identical simulations across platforms. Every subsystem decision is vetted
  against this; see [Determinism](./manual/determinism.mdx).

## A script

A script declares lifecycle methods and is attached to a node. Two languages
ship — Luau (the default) and Rune — and both call the same engine bindings:

```lua
-- scripts/spinner.luau
local Spinner = {}

function Spinner:init()
    self.angle = 0
end

function Spinner:update(dt)
    self.angle += dt
    self.node:set_rotation_euler(0, self.angle, 0)
end

return Spinner
```

## A scene

Scenes are declarative TOML. Plugins extend the vocabulary: `body` and
`collider` come from the physics plugin, `shape` from the rendering plugin.

```toml
[[nodes]]
name = "Ball"
position = [0.0, 6.0, 0.0]
script = "scripts/ball.luau"
body = "dynamic"
collider = { kind = "ball", radius = 0.5 }
shape = { kind = "ball", radius = 0.5 }
```

## What is in the engine today

- A scene tree over an ECS (`hecs`): node paths, transform propagation, a
  fixed frame schedule, and a plugin API.
- Scripting in Luau or Rune — or both in one project (`language = "mixed"`) —
  with hot reload, `require` with in-place module reload, and a
  language-neutral binding seam.
- 3D and 2D physics (rapier, with its `enhanced-determinism` feature), stepped
  on a fixed 60 Hz accumulator.
- Rendering through kiss3d/wgpu in three run modes — windowed, offscreen
  (GPU without a window, for screenshots and visual CI), and fully headless
  for tests and servers — all computing the same simulation.
- Animation: clip assets with transform, component-property, and method
  tracks, plus script-driven tweens — all on a fixed timestep.
- A shared-asset layer: content by reference or inline, one rule for every
  asset type a plugin registers.
- Networking: HTTP and websockets for scripts, with handler methods or
  `await`, delivered into the simulation once per tick — replayable. A
  Gamend backend plugin (login, REST, realtime, server hooks) on the same
  contract.
- Immediate-mode UI for scripts (egui) plus widget components for in-game HUDs.
- Audio (rodio), per-frame input snapshots covering keyboard, mouse,
  gamepads, touch, and window file drops, and a seeded deterministic `rng`
  module.
- A plugin system where the same source ships as a linked-in module or a
  run-time extension loaded from a shared library.
- An editor that is a regular Balaur project: scene tree, inspector, viewport
  with gizmos, script editing with hot reload, play-in-editor, and a keyframe
  timeline.
- Export to precompiled, reproducible packs, and fused single-file executables
  per platform.
- A headless benchmark suite that reports results as a share of one 60 fps
  frame and compares both script languages on the same scenarios.
