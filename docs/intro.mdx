# Introduction

Balaur is a node-based game engine in Rust: 2D and 3D, scripting, physics,
animation, networking, and an editor. Fast to run, fast to iterate, easy to
use.

To a game developer it is a scene tree of named nodes with scripts attached.
Underneath, every node is an ECS entity and every subsystem is a plugin —
a layer only plugin authors see. The editor is itself a Balaur project.

![The editor: scene tree, viewport, inspector](/img/editor/persona_scene.png)

:::warning

No published release yet. Balaur builds from source — see
[Getting started](./getting-started.mdx).

:::

## Two things it will not compromise on

- **Instant hot reload.** Save a script while the game runs; the new code is
  live in milliseconds and the state survives.
- **Determinism, always on.** Same inputs, same bits on every platform, and
  the engine can prove it: a fixed 60 Hz step, a digest per tick, record and
  replay. Network replies enter an ordered queue and land at the start of a
  tick, so a replay covers logins and retries without touching the network.

## A script

```rust
// scripts/spinner.rn
pub fn init(this) { this.angle = 0.0; }

pub fn update(this, dt) {
    this.angle += dt;
    this.node.set_rotation_euler(0.0, this.angle, 0.0);
}
```

## A scene

```toml
[[nodes]]
name = "Ball"
position = [0.0, 6.0, 0.0]
script = "scripts/ball.rn"
body3d = "dynamic"
collider3d = { kind = "ball", radius = 0.5 }
shape3d = { kind = "ball", radius = 0.5 }
```

`body3d`, `collider3d` and `shape3d` are components: the physics and render
plugins registered them, which also made them script calls and inspector rows.
